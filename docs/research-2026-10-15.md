## Why simply increasing seam stiffness can make the iteration budget worse

This is an independent two-variable calculation, not an AVBD implementation or a diagnosis of the missing montage. For one scalar displacement per point, consider

\[
 E=\frac a2[(x_1-y_1)^2+(x_2-y_2)^2]+\frac k2(x_1-x_2)^2,
 \qquad a=m/h^2.
\]

The Hessian eigenvalues are `a` and `a+2k`. Its condition number is `1+2k/a`. One exact Gauss–Seidel sweep satisfies `e1_new = k/(a+k) e2_old`, then `e2_new = k/(a+k) e1_new`: the slow error mode contracts by `q = (k/(a+k))²` per sweep. This is a solver-error calculation at one implicit step, not fabric stretch over time.

| k/a | Condition number | Slow-mode error left after 16 sweeps |
|---|---:|---:|
| 1 | 3 | about 2.3e-10 |
| 10 | 21 | about 4.7% |
| 100 | 201 | about 72.7% |

Large penalties can leave a local solver far from its implicit minimum even though each local update decreases energy. Mesh refinement, mass, time step and seam quadrature all change this ratio. Our seam input is N/m²; its quadrature weight in metres yields each sample's N/m coefficient. Compare that sample coefficient with the local inertial block rather than comparing UI numbers directly. This explains a research priority; it does not identify the source of visible jitter.

## AVBD experiment contract — proposed, not implemented

The [paper](https://graphics.cs.utah.edu/research/projects/avbd/Augmented_VBD-SIGGRAPH25.pdf) distinguishes finite elastic penalties from hard constraints. Hard constraints use multiplier updates; finite stiffness ramps toward its prescribed cap without adding that multiplier force. Sections 3.6–3.7 address correction-induced momentum and warm starting with decay. Carrying multipliers naively can inject energy. These details matter more than renaming VBD or multiplying stiffness.

Our proposed first experiment is a separate CPU f64 seam-only prototype against the analytic two-point system and a pinned two-panel fixture. Preserve finite material elasticity and current OGC contact. Explicitly specify whether a seam is finite or hard; never silently change old projects' meaning. Check units, force balance, residual reduction, seam gap and accepted-step energy. Include incompatible constraints, zero forcing, changes in `dt`, and interrupted/reset solves.

Dual state must have a documented lifetime: reset after remeshing, seam reversal/resampling/deletion, material edits and reload. Runtime quadrature indices are unsuitable persistent IDs. A production adapter needs stable semantic identities plus rebuilt sample mappings. Only after equal-scene CPU comparisons should an explicitly authorized GPU prototype follow. This does not yet justify a new solver selector.

## Implemented safe cost reductions

1. **Current AABB filtering of cached pairs.** The candidate envelope deliberately overcovers motion. Before exact VF/EE geometry, compare the current primitive boxes with the current query radius, with an outward floating-point margin. The box distance is a lower bound on primitive distance: if it exceeds the radius, this pair cannot reduce any distance initialized to that radius, nor supply a retained contact. The exact distance and admissibility tests still run on every surviving pair. Cache coverage, reciprocal contacts, seam exclusions, dormant terms and original detection centers are unchanged.
2. **Contact incidence coloring.** Reuse `ContactSet.incident` instead of allocating another expanded adjacency list. Store static sorted adjacency contiguously. The same vertex traversal and smallest available color preserve the previous color groups and within-group order, including dormant contact and mouse-grab terms.

The narrow-phase counter `aabb_rejections` counts saved exact pair evaluations, not removed physical contacts. CPU equivalence tests cover cache reuse/rebuild, changing query radii, local exclusions and large translated coordinates. They compare exact radii, contact keys, incidence and active counts with pruning disabled. Coloring is checked against an independently expanded conflict graph.

Measurements and reproduction commands: [CPU validation](cpu-research-validation.md). No mesh, material, time step, damping, iteration budget or GPU shader was simplified for these changes.

## Jitter investigation when the scene is available

Keep the custom scene unmodified as a regression fixture. First compare a paused render, CPU trajectory and GPU trajectory at equal physical time to separate display sampling from numerical motion. Record contact feature additions/removals, ball truncation, seam gap, extension and residual beside displacement/velocity traces; a contact count alone cannot identify feature churn. Then vary one factor at a time: iteration budget, contact refresh schedule, coordinate origin and time step.

Current hypotheses are insufficient convergence under stiff coupling, feature changes between detections, or tight/contradictory seam placement. The hybrid backend detects once per step; CPU can refresh inside a step. No friction is implemented. None of these facts proves the cause in the user's montage. Do not hide the symptom with arbitrary damping or positional smoothing and call it a solver fix.

Priority: capture the regression; profile full steps; evaluate convergence/refresh changes; move contact to resident GPU only with explicit capacity/overflow behavior and f64 comparisons. Keep the [solver comparison contract](solver-challenge.md).
