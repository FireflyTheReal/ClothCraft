# EXO feature comparison and native Rust work inventory

Audit date: 22 October 2026. This is a source/document inspection, not a runtime acceptance test of EXO. Upstream snapshot: [`352c6086b622caeda95f16d9bd923624b95e05d9`](https://github.com/mikristian/exo-sample-3d/commit/352c6086b622caeda95f16d9bd923624b95e05d9). ClothCraft baseline: [`5d54b0b`](https://github.com/erythrofr/ClothCraft/commit/5d54b0bee46d60672c9b7101e619ba245651853a), before the small initial metrics slice in this workstream.

The owner has selected **erythrofr/ClothCraft as the coordination and integration point for this native Rust effort**. This is our project's direction, not a claim that EXO's maintainer has transferred their repository, endorsed every decision, or agreed to change licenses. EXO remains an independent upstream reference and collaborator.

The executable backlog is [coordination/tasks.json](../coordination/tasks.json). Each task has bounded paths, dependencies, observable acceptance criteria, evidence and existing PR links. This document describes the differences; it is not a second assignment board.

- Public repository tree and Rust kernel manifests; source entry points for geometry, sewing, grading, markers, measurement, cost, DXF/SVG, trims, graphics, stage settings, materials, preflight, packaging and command search.
- Representative implementation bodies for grading, marker placement, costing, preflight, SVG import, unfolding and trim paths. Examples: marker placement uses conservative bounding rectangles and a limited orientation policy; the SVG importer supports a bounded browser subset; these are concrete implementations with limits, not evidence of industrial certification.

No EXO executable was launched. No GPU benchmark or feature-parity percentage was produced. No upstream source implementation, icon, private garment or example artwork was copied into ClothCraft by this audit.

## Reading the comparison

**Existing** means ClothCraft already provides the relevant foundation; there is no reason to rewrite it merely because EXO also has it. **Partial** means a specific missing workflow remains. **Missing** means no equivalent current ClothCraft module/workflow was found. **Review PR** means someone already proposed relevant work; examine it before creating a competing implementation. **Experimental** means the cited source itself has unproven mechanics, integration or release behavior.

Source presence supports an implementation lead; it does not establish usability, correctness, performance or factory suitability. Several EXO manuals describe older snapshots, so exact source links take precedence over broad historical claims.

## Integration rules

1. **Reuse ClothCraft foundations.** Do not replace stable boundary identities, material metres, cubic contours, partial-chain seams, undo/history, collision coverage or portable files with a second implementation merely for source similarity.
2. **Specify behavior before code.** Each task should close on an observable result and adverse cases. Count completed acceptance gates, not translated lines or function names.
3. **Separate mathematics, document changes, UI and outputs.** A CPU kernel can be verified independently, but it is not a user-visible feature until an actual adapter invokes it.
4. **Keep one document authority.** EXO's documented centimetre/index-oriented project subset and ClothCraft's metre/stable-boundary model are not interchangeable. Unknown fields, ID remapping and units require explicit import reports.
5. **Keep visual and physical features separate.** Textures, prints, decorative zippers and stages must not alter cloth mechanics. Visible props do not become colliders by implication.
6. **Preserve opt-in physics research.** A backend name, converted kernel or running web preview does not establish equivalent materials, contact guarantees or pull/release behavior.
7. **Review provenance before transfer.** EXO declares GPL-3.0-only; ClothCraft's original code is MIT. This audit imports no implementation. Behavioral references do not grant permission to relabel copied code. Any proposed adaptation requires its own provenance/license decision; independently authored implementations retain their actual sources and notices.
8. **Do not duplicate in-flight reviews.** PR1/6/7 share authoring/schema paths. Task claims and path scopes need to serialize those edits, even when separate agents own distinct task names.
9. **Share facts, not private sessions.** Research handoffs should link exact commits, fixtures, commands, results and limitations. Private owner garments and proprietary reference assets are not public migration fixtures.

## Deliberate exclusions

This backlog covers the inspected EXO feature families, not every button label or a guarantee of complete CLO parity. It does not import a community marketplace, proprietary brand assets, CLO SDK implementation, commercial reference garments, or unsupported opaque project formats. Animation/rigging, Alembic/USD/FBX and industrial grading dialects retain their broader [roadmap](../ROADMAP.md) prerequisites. A separate task should first define a supported, testable slice before claiming any of them.

The initial independent implementation under EXO-MFG-001 is a net rest-area/mass report, not cutting optimization, a manufacturing BOM, a persistent POM schema or a new cloth solver. Its final implementation status belongs to the task registry and its validation documentation.
